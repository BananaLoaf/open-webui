# OpenWebUI fork: обновление до v0.12.3

Проверено **2026-10-24**. Финальный upstream-тег `v0.12.3` указывает на
`91ea4e3421d1d8069f13d4a463fcb5986d94ea60`, не на RC.
Предыдущая вершина нашего форка — `688319615f446666783ca89bbe9c3101a76aa7aa`,
на базе `v0.11.4`. Ниже описаны исходники, не состояние работающего deployment.

## Сохранённые доработки

- Сохранение `response_id`, `response_status` и `incomplete_details` в
  нормализованной таблице `chat_message`, с обратным отображением в поля
  `responseId`, `responseStatus` и `incompleteDetails` диалога.
- Продолжение выбранной ветки и модели через `previous_response_id`, без
  повторной отправки уже сохранённой у провайдера истории. Поддержка
  `conversation`, корректное продолжение после выполнения инструментов,
  обработка терминальных и промежуточных статусов Responses.
- Отдельная политика Responses в
  [responses_state.py](backend/open_webui/utils/responses_state.py).
  Upstream пока не покрывает весь этот контракт и его сохранение между ходами.
- Пересылка оригинальных файлов через Files API выбранного подключения:
  текущие вложения, проверка доступа, чтение из storage, multipart upload,
  до 10 файлов и 20 MiB на файл. Изображения остаются в штатном image-пути.
  Загрузка файлов по-прежнему не запускает дублирующую обработку в RAG.
  Код: [openai_files.py](backend/open_webui/utils/openai_files.py).
- Docker: Node heap 8 GiB для сборки и получение `uv` из Docker Hub.

## Что взято из upstream при разрешении пересечений

- Общий streaming-обработчик находится в
  [utils/response.py](backend/open_webui/utils/response.py), как в upstream;
  старая копия из middleware удалена. К общему обработчику подключена наша
  политика lifecycle-метаданных. Штатная обработка отдельного события `error`
  сохранена.
- В конвертер перенесены исправления upstream: `strict: false` по умолчанию
  для инструментов Chat Completions, `tool_calls` и соответствующий finish reason
  в non-streaming ответах, очистка служебных полей при replay и восстановление
  исходного `provider_function` для Tool Search.
- Сохранён новый контракт `process_chat_payload`: четыре возвращаемых значения,
  включая `paused`, а также новые shared-chat, tool-search, compaction и
  streaming-пути upstream. Наши дополнения встроены в новую реализацию.
- Frontend и его конфигурация взяты из `v0.12.3` без собственных изменений.

## Совместимость миграций

Обе прежние кастомные миграции оставлены без изменений:

- `e2a43c7819b6` после `d4c1a8e37b62` — колонка `response_id` и backfill из JSON чатов;
- `f7d8e9a0b1c2` после `e2a43c7819b6` — статус и причина незавершённого ответа.

Upstream развивает собственную ветку от `d4c1a8e37b62` до `0bd252b206fb`.
Добавлена только объединяющая ревизия
[92b6f0c1a7d3](backend/open_webui/migrations/versions/92b6f0c1a7d3_merge_stateful_responses_with_v0123.py)
с двумя родителями: `f7d8e9a0b1c2` и `0bd252b206fb`. Она сама не меняет таблицы:
Alembic сначала применяет отсутствующую ветку, затем получает единственную
вершину `92b6f0c1a7d3`. Менять историю применённых миграций или вручную
подменять `alembic_version` не требуется.

Проверки в [test_fork_migrations.py](test/test_fork_migrations.py) исполняют
реальные миграции на SQLite и изолированном PostgreSQL из шести состояний:
пустая база, общая старая база, только первая кастомная миграция, старый форк,
чистая новая upstream-база и обе уже применённые ветки. Проверяются повторный
upgrade, сохранность Responses, паролей/MFA, исходного текста skills и версий
моделей/инструментов.

Перед production-обновлением нужен backup БД и файлов. Все экземпляры OpenWebUI
нужно обновлять совместно: upstream не поддерживает rolling update между
старыми и новыми схемами. Не запускайте одновременно старый и новый код на
одной базе. Автомиграции выполняются штатным стартовым механизмом при
включённом `ENABLE_DB_MIGRATIONS`.

Для деплоя наших доработок нужен коммит ветки `fork` либо собственный тег на
этом коммите. Upstream-тег `v0.12.3` сам по себе не содержит изменения форка.

## Проверки слияния

- 99 backend-тестов прошли, включая все шесть сценариев миграций и на SQLite,
  и на временном PostgreSQL 14 с отдельным локальным сокетом.
- 4 frontend-теста и проверка encryption artifacts прошли.
- Production-сборка `npm run build` прошла после установки зависимостей из
  нового lock-файла; локально использовался Node 23.7, Dockerfile использует Node 22.
- Исходники frontend и его build-конфигурация совпадают с upstream `v0.12.3`.
  Полная проверка типов `npm run check` не зелёная: 5696 ошибок и 188 предупреждений
  в этих исходниках; массовое исправление upstream TypeScript не входит в слияние.
- Проверки новых Python-модулей/тестов и отсутствия неопределённых Python-имён
  в объединённых обработчиках прошли. Обе старые кастомные миграции не изменены.

Проверки не подключались к production-БД и не выполняли deployment.

## Главное в серии v0.12.0–v0.12.3

Полный перечень исправлений находится в [CHANGELOG.md](CHANGELOG.md).

### v0.12.0 — 10 октября 2026

- Realtime-звонки, включая 3D-аватары; MFA с настройками обхода для OAuth.
- Совместные ответы в расшаренных чатах, авторство сообщений и live-обновления.
- Настраиваемые controls моделей, например выбор reasoning effort.
- Skills с несколькими файлами; история версий skills, моделей, tools и functions.
- Новые интерфейсы моделей и knowledge bases, сравнение версий промптов.
- Tool Search для больших наборов инструментов и сжатие контекста между их вызовами.
- Вложенные группы и модели по умолчанию для групп.
- S3 storage в slim-образе, новые возможности MCP OAuth и интерфейса MCP.

Из важных изменений эксплуатации: `ENABLE_PLUGINS` стал общим выключателем
всех типов плагинов, orjson включён по умолчанию; для Redis-кластеров и Milvus
есть отдельные требования к обновлению в changelog.

Источник: [release v0.12.0](https://github.com/open-webui/open-webui/releases/tag/v0.12.0).

### v0.12.1 — 14 октября 2026

- Внешние Apps в каналах: упоминания, ответы, карточки, кнопки и файлы.
- Compare/merge редактор для текстов, промптов и skill-файлов; экспорт `.skill`.
- Аватары в Standard-звонках и поддержка Azure OpenAI для Realtime.
- Улучшения shared chats, упоминаний и уведомлений каналов.
- Раздельные input/output token-метрики в аналитике.

Источник: [release v0.12.1](https://github.com/open-webui/open-webui/releases/tag/v0.12.1).

### v0.12.2 — 14 октября 2026

- Поддержка MinerU 4.x, Keep both в сравнении правок.
- `MODEL_ID` в custom headers и запрошенная модель в audit log.
- `call_tool` для корректной работы Tool Search со строгими провайдерами.
- Исправления автоматизаций, источников approved tools, прав доступа и SCIM.

Источник: [release v0.12.2](https://github.com/open-webui/open-webui/releases/tag/v0.12.2).

### v0.12.3 — 16 октября 2026

- Временные E2EE-чаты в личных и закрытых групповых каналах. Это не шифрование
  всех LLM-диалогов или их архивов; зашифрованные сообщения не сохраняются сервером.
- Более лёгкий Redis streaming, live-collaborators и общие поиск/доступ в workspace.
- Улучшения сравнения правок, Markdown/document previews и работы с файлами.
- Исправления OAuth refresh с `client_secret_basic`, сохранения sharing-настроек,
  PDF-экспорта и продолжения ответа при нескольких моделях.

Источник: [release v0.12.3](https://github.com/open-webui/open-webui/releases/tag/v0.12.3).
